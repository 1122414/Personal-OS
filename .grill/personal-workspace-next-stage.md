# Grill: Personal OS 下一阶段个人工作台
Date: 2026-09-29

## Intent

用户希望 Personal OS 承接随手记录、点子、不同主题的学习、与不同 Agent 的对话及近期个人状态，并能在 Mac 和安卓上随时查看记录。核心痛点是记录之后经常连记过这件事都忘了。下一版选择先完成 Mac 的记录与学习闭环（方案 A），安卓与跨端同步后续交付。

## Constraints

- 一次讨论一个关键问题；方案必须具体到生成职责、内容标准、篇幅、重点判断、编辑及展示，不能只确认“需要自动总结”。
- 随手记录必须先接住原文，不强迫分类、规划或开始聊天；需要时再进入探索。
- Agent 按需参与，不要求每次多 Agent；使用哪个 Agent 由用户自己选择。
- UI 在功能规则讨论后设计；使用 imagegen，基于当前 UI 延续设计。当前角色与“博士”属于可配置个人主题，不改写通用产品定位。
- 本轮开始整理时，工作区有其他任务的未提交实现与原始设计文件。本轮只新增讨论、设计及参考图，不把其他改动收入提交。

## Key decisions

- Decision: 默认先保存点子，提供继续讨论的路径。Reason: 灵感出现时不能增加整理负担。Alternative considered: 每条记录立即追问或自动调研。
- Decision: Personal OS 成为记录与学习讨论的主要入口，必要时使用外部专业工具。Reason: 主题背景、学习进度和原始记录能够持续连接。Alternative considered: 只汇总各个 App 的事后摘要。
- Decision: 相关学习或对话带回旧记录，同时提供每周最多 3 条的旧点子回顾。Reason: 只有关联触发，会漏掉再也没有主动提起的想法。每条说明推荐理由；允许继续、搁置或不再推荐；不凑数、不自动转待办。
- Decision: 每个学习主题保留自动生成、可修改的总结。短摘要约 60–100 字，正文通常 300–600 字；复杂内容允许更长，保留必要例子，能够复习关键理解。Reason: 同时满足快速接续与知识复习。Alternative considered: 只有进度摘要或完整聊天流水账。
- Decision: Personal OS 后台统一生成总结，首期复用 Codex 能力；原始对话即时保存，完整回复后静默 2 分钟触发整理，无新内容不重跑，也可手动更新。Reason: 避免用户每次结束学习都要手工整理。
- Decision: 总结包含目标、关键理解、未解疑问、下一步和有用的关联来源；无内容的部分省略。重点优先保留用户标记/纠正/采用的内容、理解变化、继续学习的障碍与可复用例子。Reason: 产物需要具体、可追溯，不以篇幅或 Agent 的自信程度代替重要性。
- Decision: 区分 Agent 已解释、用户自述理解、练习验证，不把讨论过写成已掌握；结论可回到原始材料。Reason: 避免总结制造虚假的学习进度。
- Decision: 用户编辑的段落保留；新生成结果冲突时提示，不静默覆盖；失败保留旧版并显示未纳入的新内容。Reason: 自动更新不能破坏用户修订或伪装为最新。
- Decision: 总结按结构保存，各部分正文支持 Markdown，能够导出 Markdown。Reason: 保持稳定阅读结构并支持代码、列表、引用及来源链接。
- Decision: 临时提问默认随问随答；有明确目标的持续主题默认带着学，可以随时跳过或改变方向。Reason: Agent 按目标与上次疑问安排解释、问题或小练习，同时保留用户节奏。
- Decision: 近期状态影响学习强度与推荐，不自动改动已确定的计划。用户明确给出的状态直接生效；没有时间范围时默认 7 天，到期停止影响建议、保留记录。可修正或提前结束。Reason: 临时状态不应成为永久判断。
- Decision: 可呈现系统观察到的事实；对个人状态的推测须由用户确认后生效。Reason: 没有记录不等于缺乏动力。明确不想开新坑时暂停需要开启新项目的旧点子推荐。
- Decision: 设备范围为 Mac＋安卓；安卓首版快速记录、查阅和修改已有内容、跨端同步，离线可用已同步内容。AI 对话与生成第一阶段在 Mac 上执行。Reason: 用户接受先满足随时记录和查看，Mac 关机时手机不产生新的 AI 回答或总结。
- Decision: 本地优先＋云端同步；两端各有本地数据，云端保存同步副本，不要求两端同时在线；支持导出，修改与删除也需要同步。Reason: 满足跨端连续使用。Alternative considered: 只在两端同时在线时直接同步。
- Decision: Codex 是当前主用工具；后续接入 DeepSeek Harness（DSH）和 Kimi CLI，DSH 未来可能更常用。主题、记录及总结归 Personal OS，各运行时会话分别保存；用户手动选择 Agent，每个主题记住选择。Reason: 允许更换 Agent 而保留个人内容和背景。
- Decision: 新笔记与总结以 Personal OS 为主要编辑版本，Obsidian 作为可选来源和 Markdown 导出目的地。Reason: 手机与桌面维护同一份内容。Alternative considered: 所有新内容以 Obsidian 为准或首期完整双向同步。
- Decision: 首版支持文字、链接、图片和 PDF；保留原始材料，明确抓取或解析不完整；保存材料不等于自动调用 Agent 分析。语音先使用系统输入法转文字，视频先保存链接。Reason: 控制首期输入处理范围并保留来源证据。
- Decision: 下一版先交付 Mac 记录→主题→Codex 持续学习→总结→旧内容关联（方案 A）。Reason: 先验证内容组织和学习体验，再扩展跨端。Alternative considered: 优先完成 Mac＋安卓的记录同步（方案 B）。

## Surfaced assumptions

- 旧 MVP 的“所有 Agent 工作必须从 Task 出发”不足以承接尚无任务的探索和学习；新记录与主题需要独立于任务存在，已有任务执行与审核流程继续保留。
- 多种 Agent 的支持不等于固定多 Agent 分工。此前的举例让用户专门纠正了这一点。
- “自动总结”不是一个足够的需求定义。用户明确要求回答谁总结、什么格式、多少字、如何判断重点、Markdown 与 UI；这些要求促成了具体的总结标准。
- 读取原始对话、保留来源与人工修订，是总结可信度的一部分；Markdown 渲染本身不能保证总结有用。
- 旧笔记回归既需要相关场景触发，也需要少量周期回顾，且必须尊重当前状态。
- 当前范围是方向、规则和概念设计的收敛，不代表学习功能、DSH/Kimi 接入或安卓同步已经实现。

## Open questions

- A 之后，多 Agent 扩展和安卓同步的具体先后顺序，依据 A 的使用结果再排期；用户尚未给出时间与成本上限。
- 云端服务、身份与密钥管理、加密和冲突合并方案，在跨端阶段单独验证与选型；接受云同步不等于已经授权购买服务或上传现有数据。
- Codex 持续会话、取消/恢复、权限交互和来源映射需要实际适配验证；不能把现有单次执行接口视为已经支持完整学习体验。
- DSH 官方 SDK/会话机制已有文档依据，但尚未做本项目集成验证；Kimi CLI 的集成接口仍待验证。
- 首轮图用于评审布局与阅读层级；生成图片文字及交互不作为已实现或最终批准的 UI 规范。

## Out of scope

- 本轮讨论不实施业务代码，不发布或部署云服务。
- A 不包含安卓客户端、云端 AI、完整 Obsidian 双向同步或固定多 Agent 自动协作。
- 不把每条想法自动变成任务；不把临时状态当永久偏好；不自动切换用户所选 Agent。
- 语音录音转写和视频内容分析不纳入首期；手机端独立 AI 暂缓。
