# Personal OS

本地优先的个人工作台。随手记录点子、笔记、资料与状态，在持续主题里和 Codex 学习，把可修改、可追溯的总结留下来；自己要做的事放进待办勾掉，要改代码或整理文件的事派给 Agent 并审核，每天生成日报。应用功能面向通用用户；「博士」和浊心斯卡蒂是当前可配置的个人主题。

## 首页

首页是一页：问候语旁是近期状态标签（点击编辑），下方为随手记、Agent 等你回复/待验收/失败提醒；左列是「今天」，右列是今日学习、阶段事项和日报卡（AI / 金融 / 法律分页显示当天摘要，下方是本周想起的点子）。窗口高度不足 800px 时问候语缩成一行，面板保留最低高度，再放不下就整页滚动。

- **今天**：今天的待办清单。输入框回车即加入今天，也可从待办池挑选；勾选即完成，可取消。昨天没勾掉的自动留在今天，标「昨天未完成」或「N 天前」。可以拖动调整顺序，也可以把待办池里的拖进来。「AI 建议先做」是可选按钮，点击才生成，最多 3 条提示，不改待办内容。

- **项目登记**：没有项目时，首页列出 Settings → 代码仓库扫描目录（默认 `~/My-Item`）下最近 30 天有提交的一级 git 仓库，勾选后一键登记为项目并填好工作目录。之后只读取已登记项目。
- **上次工作**（首页已不显示，数据仍在同步）：今天之前最近一个有活动的日子，按项目列出 git 提交、Cursor / Codex / WorkBuddy 会话标题和最后一条回复（“停在”），以及完成的任务。只有已登记项目的痕迹和任务、Agent 事件决定日期；项目外目录的 Cursor、Codex 会话单列在“其他会话”，WorkBuddy 只收录项目内的会话。应用启动时和每 10 分钟同步一次，也可手动刷新；只读取来源，不修改仓库或会话文件。痕迹同时进入当天工作日报，作为核对来源，不自动计为完成。
- **阶段事项**（原「长线事项」，点标题可整块折叠，折叠状态会记住）：读取 vault 中 `首页数据/工作台.json` 的事项及关联笔记的 `home_progress`、`home_next`、`home_status` 属性。首页修改后只写回这三个字段；若笔记已在别处改动，提示冲突且不覆盖。Obsidian 仍是长线事项的主版本。「下一步」有内容时可点「→ 今天做」生成一条今天的待办；勾掉后不改笔记，只在该事项上提示「下一步已完成，填新的下一步」，改了下一步后提示消失。

情报频道已从导航收起，数据与代码保留；学习页已恢复到侧栏，首页右栏顶部是「今日学习」。

验收记录见 [首页改造验收](docs/2026-09-29_home-redesign-verification.md)。

## 记录与学习

- 首页「随手记」无需分类，保存不会启动 Agent 或创建任务。记录可以独立保留，也可明确关联主题、转为待办或转为 Agent 任务。图片/PDF 原件随 SQLite 备份保留，单件最多 20 MB。
- 学习主题支持「带着学 / 随问随答」，使用已登录的本机 Codex CLI，按主题恢复原生会话。发送时提供主题原文、当前总结、已确认且未过期的状态及本轮勾选的资料。学习运行时只读，任务执行仍走原来的项目和审核流程。
- 每个学习主题有「卡片」页：正面写问题或概念，背面写解答（可用 Markdown）。可以自己写、编辑、删除，也可以让 AI 按主题目标生成：每个主题单独设置是否每天推送、每天几张（1–10，默认 3）和生成通道（Codex、Kimi、Claude Code、Cursor、WorkBuddy 中本机可用的），也可随时「现在生成」。生成时附上已有卡片的问题以免重复；失败会在主题里显示原因，不影响已有卡片。每日推送在客户端开着的 8–20 点之间对当天还没推送的主题各生成一次，没开客户端的日子不补发。同一主题同时只允许一次生成；手动生成成功也算当天已推送。卡片页一次显示一张，点击翻面看答案，左右切换，到期的卡片翻面后评分；全部卡片在「管理全部卡片」里。
- 卡片参考资料：主题「资料」页可以上传 md / txt / pdf（PDF 提取文字后使用），关联到主题的记录默认都参与生成，可以逐份取消「用于卡片」；学习页的「通用参考」写给所有主题（答题风格、深度、你的背景等），只用于生成卡片。生成时，简历这类背景资料决定出什么题、答案联系你的经历；笔记、讲义这类知识资料是答案的第一依据；资料没有的内容单独一段，以「资料外补充：」开头。每张卡片记下依据的资料名称。资料合计最多约 6 万字，超出会截断并提示。在主题里上传的文件只属于这个主题：不出现在「记录」、全局搜索和旧记录回想中，资料页显示「删除」（原件一并删除）；从记录关联进来的仍显示「取消关联」，记录本身保留。
- 首页「今日学习」逐张显示到期卡片（先复习、再新卡），看答案后选忘了 / 模糊 / 记得：忘了明天再来并从头开始；模糊 3 天后再来、间隔不升级；记得依次间隔 7、14、30 天，在 30 天那档再记得就算已掌握，不再出现，可在主题的「已掌握」里恢复复习。
- 配置了 Obsidian vault 时，当天生成或新写的卡片写入 vault 的 `学习卡片/<日期>.md`，按主题分组；当天卡片有变化时整份重写，是只读副本，修改在 Personal OS 中进行。验收见 [学习卡片验收记录](docs/2026-09-30_learning-cards-verification.md)。
- 资料保存、提取文字、发送给 Agent 是分开的操作。网页只提取静态文字；PDF 使用 Mac PDFKit 提取页内文字，不做 OCR，不宣称已读懂图表或视频。图片按本轮选择发送原图，失败会显示原因。
- 完整回复后空闲约 2 分钟，Codex 在后台整理总结；也可手动更新。接续摘要约 60–100 字，正文通常 300–600 字，按目标、理解、疑问、下一步与相关内容组织。长度是生成目标，不是硬截断。
- 总结支持安全 Markdown、来源快照和原文跳转。各部分可编辑并自动保存；人工修改受保护，AI 后续变化以候选呈现，可逐部分恢复历史。没有练习核对记录时不会把解释过当作已经掌握。
- 近期状态保留原话和期限，默认 7 天，可修正或提前结束；推测须确认后才生效。只影响新建议，已确认计划由你调整。对话保留当次参考的状态快照，过期后不会继续约束新建议。
- 旧记录按主题目标和最近问题中的共同词语给出可核对的关联理由；上下文最多 3 条，每周回顾最多 3 条，支持继续、搁置 7 天、不再推荐。原文始终保留，不会自动转任务。「不开新项目」生效时仅推荐明确属于已有事务的内容；可在记录编辑中修正回顾偏好。

「待办」页分待办池、今天、已完成三栏，可移入移出今天、归档和取消归档。原来的今日计划确认已停用，旧数据保留不删；升级后首次启动时，原先「我自己」执行且没有派过 Agent 的任务会自动转成待办池里的待办（转换前自动备份，只执行一次）。Mac 应用运行时才进行总结和周回顾，重开后恢复待处理内容，不补发多周提醒。Android、云同步、DeepSeek Harness 和 Kimi CLI 属于下一阶段，当前未接入。

## macOS 客户端

构建需要 macOS、Swift 命令行工具、Python 3.12+，以及 Node.js 20.19+ 或 22.12+。在项目根目录执行：

```sh
npm ci
./scripts/build-macos-app.sh
open 'build/Personal OS.app'
```

构建结果是 `build/Personal OS.app`，可从 Finder 双击打开。界面在独立客户端窗口运行；应用自动启动仅监听本机的后台服务并在退出时停止。它仍需本机安装 Python 3.12+，当前构建不包含独立的 Python 运行时。重新构建应用会更新界面和服务代码，不会删除用户数据。

客户端数据保存在 `~/Library/Application Support/Personal OS/personal-os.sqlite3`。首次启动时，若原网页原型的 `data/personal-os.sqlite3` 存在且客户端数据尚不存在，会复制原数据一次；不会覆盖客户端已有数据。诊断日志位于同目录的 `desktop.log`。测试时可用 `open -n --env PERSONAL_OS_DATA_DIR=/tmp/某目录 'build/Personal OS.app'` 另开一个使用独立数据目录的实例，不读写真实数据库。

开发前端或 API 时，仍可分别运行 `python3 -m server.app` 和 `npm run dev`；开发服务器会将 `/api` 代理到本地后端。网页原型的数据默认保存在 `data/personal-os.sqlite3`，与客户端数据分开。

可在 Settings 中填写 Obsidian vault 路径，或首次启动前设置 `PERSONAL_OS_OBSIDIAN_VAULT` 环境变量。学习资料页可引用选定笔记的只读快照；记录和总结可明确导出 Markdown 至本地或 vault 的 `Personal-OS/` 文件夹，附件一并复制，每次使用独立目录，不覆盖旧文件。任务知识写入仍在审核页批准：侧栏不再显示「审核」，有待确认的知识写入时 Agent 任务页顶部会提示并链接过去。这些入口不做双向同步，Personal OS 中的记录和总结是主版本。

「Agent 任务」只用于交给 Agent 执行的事，必须挂在设置了本地工作目录的项目下并选定通道；没有目录的项目不能派任务。新建表单只有标题、要求与完成标准、项目、执行通道和模型，可「创建」或「创建并派出」；项目详情里也有「派个 Agent 任务」入口。待派出和失败或取消的任务可在详情里选通道和模型后派出：

| 通道 | 命令行 | 写入范围 | 状态 |
|---|---|---|---|
| Kimi | `kimi -p --output-format stream-json`，接着说时加 `-S <会话编号>`（已验证 2.1.1） | macOS `sandbox-exec` 只允许写工作目录、`~/.kimi-code/`、`/tmp` 和系统临时目录 | 本机真实派单与多轮续接已验证 |
| Claude Code | `claude -p --output-format stream-json`，自动接受编辑并允许 Bash，接着说时加 `-r <会话编号>`（2.1.199） | 同上，状态目录为 `~/.claude*` | 本机模型服务余额不足，待实测 |
| Cursor | `cursor-agent -p --output-format stream-json --force --trust --sandbox disabled`，接着说时加 `--resume <会话编号>`（2026.09.28，需先 `cursor-agent login`） | 同上，状态目录为 `~/.cursor/`（Cursor 自带沙箱关闭，避免与外层 `sandbox-exec` 嵌套） | 本机真实派单、多轮续接、越界写入被拦截已验证 |
| WorkBuddy | 自带的 CodeBuddy CLI（`/Applications/WorkBuddy.app/.../cli/bin/codebuddy`，2.156.0），参数同 Claude Code；它是 node 脚本，客户端用 WorkBuddy 自带的 Electron 运行（`ELECTRON_RUN_AS_NODE=1`），不依赖本机装 node | 同上，状态目录为 `~/.codebuddy` | 需先在终端运行该命令并输入 `/login`；未登录时会显示「Authentication required」并标为失败。登录后的真实派单待验证 |
| Codex | `codex exec -s workspace-write` | Codex 自带的工作区写入沙箱 | 客户端使用 Codex 桌面版（ChatGPT.app）自带的 codex-cli，本机真实派单已验证；终端 PATH 中没有 |
| Multica | 见下文 | 由 Multica 执行环境决定 | 未在真实服务端验证 |

模型留空时用该 CLI 自己配置的默认模型；填了就每一轮（包括接着说）都传给 CLI：Codex、Kimi 用 `-m`，Claude Code、Cursor、WorkBuddy 用 `--model`。输入框的候选来自本机：Kimi 读 `~/.kimi-code/config.toml` 中配置的模型，Codex 读 `~/.codex/models_cache.json`，Cursor 问 `cursor-agent models`，WorkBuddy 读 `codebuddy --help` 中列出的模型，Claude Code 提供 sonnet / opus / haiku；候选缓存 10 分钟，也可以手填。换通道时模型清空。Multica 由其 Agent 决定模型，不提供选择。

各通道命令路径在「设置 → 连接器与运行环境」填写，留空则在 PATH 中查找（Multica 留空即不启用）；找不到的通道不会出现在派出选项中。任务页可在列表与看板之间切换，看板按待派出、运行中、等你回复、待验收、已完成、失败或取消分列，卡片显示通道、用时和最后一行日志；任务详情是一段对话：任务要求、每轮 Agent 的回复（工具调用折叠为「执行了 N 步」，每轮日志可展开）和你的消息依次排列。每轮结束后，Agent 在问你问题（需要澄清或做选择）时任务进入「等你回复」，这一轮做完时进入「待验收」。系统要求 Agent 提问时在回复最后单独写一行【需要你回复】，据此区分，显示时去掉这行；Agent 漏写时会落到「待验收」，问题仍在对话里。两种状态下都可以在底部输入框接着说（Enter 发送，Shift+Enter 换行），运行中只能取消、不能插话，但能实时看到 Agent 已说的话和执行到的步骤（约 1.5 秒刷新，末尾显示「正在执行 · 最近一步」；停在对话底部时自动跟随）。Kimi、Claude Code、Cursor 接着原会话继续；Codex、Multica 每轮开新会话，并在提示里附上此前的对话（最近 10 轮）。原会话无法续接时自动开新会话重试一次，并在这一轮标出。随时点「结束并验收」查看从第一轮到现在的累计改动，只有人工确认才将任务标为完成，失败或取消后也可以验收。客户端不在前台时，一轮结束会弹 Mac 系统通知（等你回复、待验收、失败；自己取消的不通知），点击通知打开客户端并跳到该任务的对话；第一次通知时系统会请求授权，之后可在「系统设置 → 通知」中关闭。Agent 写文件工具指向工作目录以外的路径会在执行详情和审核页标出。直连通道随客户端退出而终止并标为中断，需要人工重试。AI 简报、项目脉搏、日报整理和学习仍通过本机 Codex CLI 生成。若运行时不可用，基本计划与日报仍根据本地事件运行，并明确显示执行错误。第二阶段验收见 [Agent 派单与看板验收记录](docs/2026-09-29_phase2-verification.md)。

Agent 执行时会将任务描述、项目约束和规则交给所选通道；AI 建议会发送相关任务、项目、决策与规则上下文。系统对工作目录做执行前后快照，在 Review 中列出检测到的文件变更，跳过隐藏目录和常见依赖/构建目录，最多记录 20,000 个文件。确认 Agent 结果前应核对真实工作目录。HTTP API 只监听本机，并拒绝非本机来源的写请求。

### 开源 Multica 通道（可选，尚未在真实服务端验证）

Multica 通道只调用 `multica` 命令行的 JSON 输出（`issue create / runs / run-messages / cancel-task / rerun`），不读取 Multica 数据库。一个 Personal OS 任务对应一个 Multica issue，issue 编号记在执行记录上；客户端关闭时 Multica 上的执行继续进行，重启后按编号继续跟踪，不标为中断。解析所用的 JSON 字段来自手写样例（CLI 0.4.14 的帮助说明），**尚未与真实服务端核对**，首次接入时请先用一个小任务验证。

Multica 自建服务端需要 Docker（PostgreSQL 17、Go 后端、Next.js 前端），适合能使用 Docker 的机器：

1. 按 Multica 开源仓库的自建说明，用 Docker 启动服务端（CLI 默认连接后端 `http://localhost:8080`、前端 `http://localhost:3000`）。
2. 安装命令行（macOS 可用 `brew install multica`），用独立配置档连接自建服务端并登录、启动本机 daemon：`multica --profile work setup self-host`；服务端不在本机时加 `--server-url` 和 `--app-url`。
3. 在 Multica 中配置 Agent 与仓库后，用 `multica --profile work agent list --output json` 确认要指派的 Agent 名称。
4. 在 Personal OS「设置 → 连接器与运行环境」填写 Multica 命令路径（如 `/opt/homebrew/bin/multica`）、配置档 `work` 和 Agent 名称，保存后任务即可选择 Multica 派出。命令路径或 Agent 名称留空时不启用。

Multica 的 Agent 在 Multica daemon 所在环境执行。只有它改动的是项目设置中的本机工作目录，Personal OS 才能在审核中列出文件变更；否则请在 Multica 中核对改动。

Intelligence 频道（当前已从界面收起）支持每行一个 RSS/Atom 来源地址、关注关键词、排除关键词和每日上限。刷新后，来源时间、收录时间、刷新错误与用户反馈保存在本地；忽略项不进入简报，收藏/忽略暂不训练推荐模型。

AI 日报直接读取 Obsidian 已落盘的 Markdown，分模块：默认 AI（`每日AI/YYYY-MM-DD/*.md`）、金融（`每日金融/…`）、法律（`每日法律/…`），可在 Settings → 日报来源增删模块、改名称和 vault 内的相对目录（最多 10 个；只读取这里配置的目录）。首页日报卡按模块分页，每页显示该模块最近一期主报告（同一天多篇时取排在最前的一篇，AI 模块即 `AI日报…` 那篇）自带的摘要，不调用 AI：依次找「今日三句话」「导语」「执行摘要」「今日结论」「摘要」这几个标题、callout（如 `> [!summary] 今日三句话`）或加粗标签（如 `> **导语**：`），都没有时取第一段正文；点标题或「阅读全文」打开原文。想让摘要稳定，可在 WorkBuddy 的日报提示词里固定要求：在标题下方先输出 `## 今日三句话`，用 1. 2. 3. 编号列出今天最重要的三件事，每句不超过 80 字，再写正文。导航中的「AI 日报」页选日期后按模块分组（可折叠）阅读全文；每 30 秒检查文件更新，也可手动刷新。今天尚无报告时明确显示最新报告日期。报告只读，工作台中的勾选框只展示原笔记状态；不会修改原笔记。支持常用 Markdown、表格、代码和 HTTP(S) 原文链接，HTML 作为文字显示、图片不自动加载。最多展示最近 366 个日期目录和 2,000 篇，单篇上限 512 KB，超限显示提示。

WorkBuddy 会话导入的历史会话入口已从界面收起，已导入数据保留；会话摘要不进入首页或 AI 简报（首页“上次工作”只读取项目内会话的标题和时间）。Settings 中可以展开会话同步配置，但读取 AI 日报不依赖它。当前本机已停止原会话自动同步。该适配仍针对 WorkBuddy 5.6 本地格式，已导入数据保留；不读取认证/推理/工具日志，不修改源数据。

Settings → 外观主题可调整 0–100% 的界面背景透明度，拖动即时预览，保存后跨重启保留，三套主题共用。透明度作用于面板与侧栏背景，文字保持不透明。

「工作日报」（原「历史」）按日期显示日报和当天完整时间线。日报分「今日工作总结」和「明日工作计划」两部分：选一个生成通道（Codex、Kimi、Claude Code、Cursor、WorkBuddy 中本机可用的，记住上次选择），依据当天完成和没完成的待办（含优先级）、待办池里的高优先级待办、待验收或失败的 Agent 任务、代码提交与会话、决策、复习卡片数和个人规则中的日报规则归纳；笔记变化和外部资料只作线索，不算完成。也可以「不用 AI，按记录生成草稿」。重新生成会保留旧稿；出现新事件后提示过期，确认前需核对。首页的日报按钮跳到这一页。生成日报、AI 生成卡片、同步痕迹这类耗时操作在后台进行，期间可以照常新建和派出 Agent 任务、保存其他内容，列表也照常刷新。过去日期可以补记；晚上 8 点后的自动草稿和其他自动化仍只在应用运行时工作。

「待办」每条有低 / 中 / 高优先级标签（默认中，点一下切换），只作标记；顺序由拖动决定，待办池、今天和首页的今天都能拖，也能在待办池和今天之间拖。每晚 8 点弹框列出今天还没完成的待办，可以直接勾掉；8 点时没开客户端，当晚打开时再提醒；每天最多一次，点「知道了，今晚不再提醒」后当晚不再弹出；客户端不在前台时同时发 Mac 通知。

Settings 提供数据库备份、JSON 导出及恢复入口。恢复前自动保留当前数据库，运行任务期间禁止恢复。备份不包含项目文件与 Obsidian 笔记。Agent 任务可归档、恢复，已完成的可重新打开。
