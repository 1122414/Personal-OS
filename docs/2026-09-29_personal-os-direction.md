# Personal OS 方向调整：从"等我录入"到"替我收集和统筹"

日期：2026-09-29

状态：方向已与用户讨论确认；第 6 节是第一步的规格。第三阶段（[计划](2026-09-29_phase3-plan.md)、[验收](2026-09-29_phase3-verification.md)）调整了首页、每日流程和模块边界，见第 4 节。第 8 节列出未定事项。

## 1. 为什么调整

用户希望把绝大部分工作的入口放在 Personal OS，但实际上不想打开它。讨论中确认的原因：

- **打开是空的。** 正式客户端中任务、项目、记录、学习主题均为 0。首页内容全靠手动录入，而实际工作发生在 Cursor、各代码仓库和 Obsidian，Personal OS 不从这些地方读取。
- **流程和概念太重。** 9 个导航页、约 10 类对象、首页拆成"个人工作台 / 今日计划"两个标签；每一步都需要用户主动操作，回报却要等到第二天。
- **Agent 分散没有解决。** 应用内只能调用 Codex，而且是非交互执行；学习对话是只读、无联网的受限版本。在 Cursor 里做的工作完全看不到。
- **功能是照着规格做的，不是被使用推出来的。** 原定的 7 天试用没有进行，就进入了下一阶段。

## 2. 定位

- **Personal OS 是真正的首页**：每天第一个打开，负责"今天看什么、做什么、做过什么"，以及统筹各个 Agent 的工作。
- **Obsidian 是笔记首页**：笔记和知识的主版本仍在 Obsidian；长线事项的进度也以 Obsidian 为准。
- **Personal OS 是一个完整的产品**：任务、看板、审核、日志都在 Personal OS 中完成，不要求用户打开 Multica 等执行工具。执行工具只是藏在后面、可以替换的通道。

## 3. 数据归属

| 内容 | 主版本 | Personal OS 的做法 |
|---|---|---|
| 代码工作 | git 仓库、各 Agent 的会话记录 | 只读汇总 |
| 笔记、知识 | Obsidian | 引用；需要时把记录整理成笔记写入 |
| 长线事项（如秋招准备、硬知识学习） | Obsidian 笔记属性 `home_progress` / `home_next` / `home_status`，入口列表来自 `首页数据/工作台.json` | 读取并显示；可在首页修改，写回笔记属性 |
| AI 日报 | Obsidian `每日AI/` | 只读展示（已实现） |
| 随手记 | Personal OS 数据库 | 录入、查看、转出 |
| 待办（自己做的事）、Agent 任务、Agent 运行、审核、日报 | Personal OS 数据库 | Personal OS 独有 |

## 4. 已确认的产品决定

### 首页

打开后看到四块内容，顶部是随手记输入框，问候语旁是近期状态标签：

1. **今天**：今天的待办清单（第三阶段起只放待办，不放 Agent 任务）。
2. **上次工作**：上一个有活动的日子里做了什么（周一打开看到的是上周五）。
3. **长线事项**：来自 Obsidian 的进度和下一步；下一步可一键加入今天的待办。
4. **紧凑栏**：AI 日报最新一篇和本周想起的点子，各一行。

首页不再分成两个标签。窗口不够高时问候语缩成一行，面板保留最低高度，再放不下就整页滚动。

### 模块边界（第三阶段确认）

| 模块 | 是什么 | 有没有「完成」 | 从哪来 |
|---|---|---|---|
| 记录 | 随手记下的点子、资料、状态 | 没有，只保留和转出 | 首页输入框 |
| 待办 | 我自己要做的事，勾掉即完成 | 有，勾选 | 手动添加、记录转入、长线事项的下一步 |
| Agent 任务 | 交给 Agent 在某个项目目录里改代码或整理文件 | 有，必须经过审核 | 手动创建、记录转入、情报深入研究 |
| 项目 | 一个有本地目录的代码或文件仓库 | 手动标为已完成 | 登记仓库或手动创建 |
| 长线事项 | 秋招准备这类持续数周的目标 | 在 Obsidian 里标状态 | Obsidian `首页数据/工作台.json` 与笔记属性 |

- 不写代码的事（如「准备字节面试」）是待办，不是 Agent 任务。
- Agent 任务必须挂在有本地目录的项目下，并选定执行通道；没有目录的项目不能派任务。
- 长线事项的内容始终以 Obsidian 为准。它的下一步生成的待办勾掉后，Personal OS 不改笔记，只提示「下一步已完成，填新的下一步」。

### 每日流程

第三阶段起改为四步，去掉「确认今日计划」：

1. **放进今天**：直接在「今天」输入，或从待办池、长线事项的下一步挑进来。昨天没做完的自动留在今天，标「昨天未完成」或「N 天前」。
2. **做完勾掉**：勾选即完成，可以取消。
3. **日报自动起草**：由勾掉的待办、审核通过的 Agent 任务、Agent 失败事件、git 提交和会话生成。
4. **晚上核对并结束今天**：想改才改，确认后当天定稿。

AI 只做可选的「建议先做」提示（点击才生成，最多 3 条），不替你排计划、不改待办内容。旧的今日计划数据保留在库里，不再显示。

### 随手记

- 存在 Personal OS 数据库。
- 需要两个入口：全局快捷键弹出小输入框（在任何应用中都能记录）、手机端（见第 8 节未定事项）。
- 出口：整理成 Obsidian 笔记；**只在用户主动要求时**才交给调研 Agent，结果挂回该记录下。点子较多，不自动调研。

### 收起的功能

以下功能从导航和首页隐藏，代码和数据暂时保留，之后再决定是否删除：

- 情报中的 RSS 频道和 WorkBuddy 历史会话（AI 日报阅读保留）。
- 学习主题中的 Codex 对话与自动总结。

### Agent 统筹

目标能力：统一看板、手动指派、自动建议交给谁、定时任务、大任务拆分并行。

- **派出去**：在 Personal OS 中创建任务，指派给某个 Agent 执行，结果回到 Personal OS 审核。
- **收回来**：用户在别处自己开启的会话（Cursor、Codex、WorkBuddy 等）也被记录，进入"上次工作"和对应项目。
- 第一批接入：Codex、Kimi CLI、WorkBuddy；ZCode 用户尚未开始使用，之后再接。长期目标是接入用户想用的各个 Agent。

## 5. 架构方向

```text
Personal OS（任务 / 看板 / 审核 / 日报 / 首页）
        │
   运行时接口：启动、状态、日志、取消、结果
        │
        ├── Multica 通道 → Codex、Kimi CLI、Claude Code 等
        ├── 直连通道 → 现有 Codex 调用（Multica 跑通前继续使用）
        └── ……以后可替换或新增

   观察来源（只读）：git 提交、Cursor 会话、Codex 会话、WorkBuddy 本地记录
```

- 任务、运行、审核的数据模型归 Personal OS，不依赖 Multica 的内部模型，与 [V0.1 产品设计](Personal-OSV0.1产品设计.md) 第 23 节一致。
- 定时任务可以在底层使用 Multica autopilot，但界面和配置都在 Personal OS 中。
- 用户不打开 Multica，意味着日志、进度、取消、重试等界面需要 Personal OS 自己实现。

## 6. 第一步规格：首页改造（只读汇总）

本步不派发任何 Agent 任务，不依赖任何 AI 运行时可用。

> **实现状态（2026-09-29）**：范围 1–7 已实现，验收见 [首页改造验收记录](2026-09-29_home-redesign-verification.md)。H02 的“跳到原始来源”只显示提交哈希和会话文件名，不能点击；H05 未在 Obsidian 中确认插件显示新值；7 天体验验收尚未开始。实现中补充的规则：只有已登记项目的痕迹决定“上次工作”的日期，WorkBuddy 只收录项目内的会话，以免定时任务带偏日期。

### 范围

1. **首页合并**：去掉"个人工作台 / 今日计划"两个标签，按第 4 节的顺序排成一页。有待审核或失败的 Agent 任务时，额外显示一条提醒。
2. **项目冷启动**：首次进入或项目为 0 时，列出最近 30 天有提交的 git 仓库供勾选（候选来自扫描 `~/My-Item` 的一级子目录），勾选后一键登记为项目并填好工作目录。此后只扫描已登记项目的目录。
3. **上次工作**：
   - 找出最近一个有活动的日子（今天之前），活动包括 git 提交、Cursor 会话、Codex 会话、WorkBuddy 会话和 Personal OS 任务事件。
   - 按项目分组，展示提交说明、会话标题和最后一条可见内容（"停在哪里"）。无法归到项目的会话单独列出。
   - 不调用模型，按规则分组；每条可追溯到原提交或原会话。
4. **长线事项**：读取 `首页数据/工作台.json` 中的事项及其关联笔记属性，显示进度、下一步和状态。在首页编辑后写回笔记属性，只修改这三个字段；写入前检查文件是否已在别处改动，若已改动则提示重新加载，不覆盖。
5. **AI 日报**：从现在的第二个标签移到首页，复用现有读取逻辑。
6. **日报纳入痕迹**：当天日报草稿加入已登记项目的 git 提交和会话条目，作为可见来源；原有"草稿过期"检查同样覆盖这些来源。
7. **导航收起**：隐藏学习页；情报页只保留 AI 日报。

### 暂不包含

勾选完成的自动提示、全局快捷键、手机入口、Multica 接入、自动建议、定时任务、拆分并行。

### 验收

| ID | 场景 | 合格结果 |
|---|---|---|
| H01 | 项目为 0 时打开首页 | 列出最近有提交的仓库；勾选后登记为项目，工作目录正确 |
| H02 | 上一个工作日在两个项目有提交、在 Cursor 有会话，今天打开 | "上次工作"显示那一天，按项目列出提交和会话，可跳到原始来源 |
| H03 | 周一打开，周末无活动 | 显示上周五（或最近有活动的一天），而不是空白 |
| H04 | 未登记的仓库有提交 | 不出现在"上次工作"中 |
| H05 | 在首页修改长线事项的下一步 | 对应笔记只有 `home_next` 改变，其余内容不变；Obsidian 首页显示新值 |
| H06 | 修改前该笔记已在 Obsidian 中被改过 | 提示冲突，不覆盖 |
| H07 | Codex 等 AI 运行时不可用 | 首页四块内容正常显示，没有报错 |
| H08 | 今天有提交后生成日报 | 草稿列出这些提交；之后再有新提交时提示草稿过期 |
| H09 | 原有计划、任务、审核、日报流程 | 行为不变，现有测试通过 |

体验验收：连续使用 7 天，记录每天是否先打开 Personal OS、"上次工作"是否准确、因缺什么而离开的次数。这一项需要真实使用，不能用测试代替。

## 7. 推进顺序

| 步骤 | 内容 | 进入下一步的条件 |

| 1 | 首页改造（第 6 节） | 7 天试用，首页成为每天第一个打开的地方 |

## 8. 未定事项与风险

- **手机入口与同步冲突。** 用户使用安卓，选择借 Obsidian 手机端中转，但目前 Obsidian 在手机和 Mac 之间没有同步。需要先选择同步方式（例如 Syncthing 点对点同步、Remotely Save 插件配合坚果云 WebDAV），或者推迟手机入口。
- **Codex 命令行不在终端 PATH 中**，只发现 `@tencent/codex-internal` 包。尚未在桌面应用内验证；若应用同样找不到，现有 Codex 派单、AI 简报和日报整理都会失败。
- **Multica 尚未配置**（`multica setup` 未执行），且需要登录其服务。需确认任务内容和代码是否会经过 Multica 服务器，这关系到本地优先原则。从二进制判断它支持 Codex、Kimi、Claude Code、CodeBuddy、Cursor Agent 等，但还没有实际跑通。
- **WorkBuddy 和 ZCode 可能无法派单。** WorkBuddy 是桌面应用，本机没有命令行；目前只能观察（已有只读适配）。ZCode 本机未安装。
- **Cursor 会话记录稀疏**：本机共 22 份，过去 7 天 4 份，只能作为 git 提交的补充。需确认它覆盖哪些类型的对话。
- **长线事项写回 Obsidian** 与"纸间 · 首页工作台"插件写同一批字段，需要实际验证两边交替修改时不会互相覆盖。
