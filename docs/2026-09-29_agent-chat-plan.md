# Agent 任务对话化计划

日期：2026-09-29

## 目标

Agent 任务的详情从「一次执行 + 日志」改成像 Cursor、Codex 那样的轮次式对话：Agent 回复后，用户在输入框里接着说，发到同一个会话；随时可以「结束并验收」，验收看的是从第一轮到现在的累计改动。

用户已确认的选择：

- 轮次式对话：Agent 运行中不能插话，只能取消；回复后再接着说。
- 验收方式：对话中随时点「结束并验收」，看累计改动；不是每轮都审核。
- 沙箱继续放行 `/tmp` 作为 Agent 的草稿区，真正的改动仍只在项目目录中。

## 已核对的前提

- Kimi 2.1.1：`kimi --output-format stream-json -S <会话编号> -p "…"` 能接上同一会话，第二轮能答出第一轮的内容，会话编号不变（在 `/tmp/pos-chat` 实测）。会话编号无效时退出码为 1，且没有任何回复。
- Claude Code：`-r <会话编号>` 可恢复会话（帮助说明，未实测，本机模型服务余额不足）。
- Codex：当前以 `--ephemeral` 运行，不保存会话；Multica 没有续接会话的命令。这两个通道每轮开新会话，并在提示中附上之前的对话。

## 设计

- 每一轮对话仍是一条执行记录（`agent_run`），新增：
  - `message`：这一轮用户说的话（第一轮为空，显示任务的要求与完成标准）。
  - `transcript`：从 stream-json 中拆出的 Agent 回复文字和工具调用，按顺序保存，工具调用只存一行摘要。
  - `resumed`：这一轮是否接在原会话上。
- 新操作 `send_agent_message {task_id, text}`：任务处于「等你回复」或「失败或取消」时可用。
  - 同一通道且有会话编号：带上会话编号续接，提示只包含新消息和收尾要求。
  - 否则：开新会话，提示包含原任务、项目约束、之前每一轮的用户消息和 Agent 回复（截断），以及新消息。
  - 续接失败且没有任何回复时，自动改为开新会话重试一次，并在这一轮标注。
- 状态：`Review` 显示为「等你回复」；「结束并验收」即原来的确认完成，在「等你回复」和「失败或取消」时都可以点。
- 累计改动：同一文件在多轮中的变化合并为一行（先新建后修改仍显示新建，新建后删除则不显示）。
- 原来「要求 Agent 继续修改」的弹窗由对话输入框取代；审核页的「继续修改」改为跳到任务对话。

## 阶段

1. 本计划文档。
2. 后端：通道续接参数、transcript 解析、`send_agent_message`、续接失败兜底、测试。
3. 前端：对话流、输入框、结束并验收、状态名与累计改动。
4. 在 `/tmp` 临时仓库用 Kimi 真实跑两轮，写验收记录，更新 README，重建客户端。

每阶段测试后中文提交。

## 风险

- 任务详情区较窄，长回复会挤；先在现有分栏里做，用过后再决定是否单独开宽的对话页。
- 回复解析依赖各 CLI 的 stream-json 格式，CLI 升级后可能要跟着调整。
- Claude Code 的续接未实测。
