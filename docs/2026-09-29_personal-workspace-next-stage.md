# Personal OS 下一阶段：Mac 记录与学习闭环

日期：2026-09-29

状态：产品讨论已收敛；以下是待实现、待验收的规格，首轮 UI 概念图用于后续评审。

决策依据：[讨论记录](../.grill/personal-workspace-next-stage.md)

## 1. 下一版的结果

用户选择方案 A：在 Mac 完成“随手记下点子 → 延伸为学习主题 → 与自己选择的 Agent 持续讨论 → 形成可修改、可复习的总结 → 学习时找回相关旧记录”。

Personal OS 承接尚未形成任务的探索、学习与个人状态，同时保留已有任务、项目、执行审核和工作日报。记录可以一直只是记录；用户明确要落实时，才进入现有任务或项目流程，并保留来源关联。

这一版先把 Codex 的持续学习体验做好。DSH、Kimi CLI、云同步与安卓属于后续路线，不作为 A 的发布前提。

## 2. 随手记录与学习主题

- 先保存原文和时间，不要求先填写标题、分类、项目或完成标准，也不自动开始对话或调研。
- 用户可从记录开始讨论，或建立持续学习主题。主题容纳相关记录、资料、对话和总结，与 Task 分开，不继承任务完成状态机。
- 记录和引用保留稳定身份，从记录进入主题或任务后仍能回到原始内容。
- 系统建议关联旧记录时解释原因，不改动原记录，不自动合并无关主题。
- 新笔记、主题总结以 Personal OS 为主版本。既有 Obsidian 内容按需引用，用户选择后导出 Markdown；首期不做完整双向同步。

## 3. 材料输入

| 材料 | 首期行为 | 必须显示的边界 |
|---|---|---|
| 文字 | 保存、编辑原文，按需加入对话 | 人工内容与生成内容可区分 |
| 网页链接 | 保存地址与可获得的标题，需要解读时读取内容 | 抓取失败、只取得部分正文或内容变化须说明 |
| 图片 | 保存原图，用户选择后交给实际支持图片的运行时 | 不支持、识别失败或只取得提取文字时，不冒充看过原图 |
| PDF | 保存原文件，解读保留文件及页码/段落定位 | 解析失败、截断、扫描页未识别须可见 |
| 语音 | 系统输入法转文字 | 不承诺保存录音或独立转写服务 |
| 视频 | 保存链接与用户笔记 | 不承诺自动转录或完整视频理解 |

“已保存”“已解析”“Agent 已使用”是不同事实。单纯收藏不触发模型分析。外部材料是内容来源，不获得执行指令的权限。

## 4. 学习对话与 Agent

临时问题默认随问随答，用户控制讨论节奏。有明确目标的持续主题默认带着学：根据目标和上次疑问安排一小段解释、提问或练习，根据回应继续；用户随时跳过、改方向或切换模式。

A 默认使用 Codex。后续多运行时接入后，每个主题记住用户选择，系统不自动切换。Personal OS 保存可见消息、资料引用、报告及回复来源；换 Agent 时携带目标、总结、未解问题和必要原文，各原生会话分别保留。

文本背景交接不代表工具、Skills、权限或运行中任务均已迁移。每个接入须声明并验证实际能力。原始消息及时落盘，流式回复、失败、取消与重启恢复有明确状态；失败不丢用户问题，不制造成功总结。本地执行延续既有工作目录和审核边界，学习主题不自动获得所有项目的执行权限。

## 5. 总结的内容合同

### 生成职责与时机

Personal OS 调度统一后台总结任务，A 先复用 Codex。输入为本主题原始对话、引用材料、既有总结和人工修订；重要结论回查原文，避免连续压缩摘要丢失证据。

完整回复后静默 2 分钟，有新增内容才触发整理；也可立即更新。生成期间保留原报告，记录本次纳入的消息/材料版本与时间。期间新增内容须明确显示尚未整理。原始对话保存与报告生成分离；失败保留原始数据和旧报告，支持重试。应用关闭时未完成的整理记为待处理，下次运行恢复；不承诺 Mac 关机后继续生成。

### 篇幅与结构

| 部分 | 标准 |
|---|---|
| 接续摘要 | 约 60–100 个中文字：目标、上次停在哪里、最重要的未解问题 |
| 完整总结 | 通常 300–600 字；能够复习关键理解，必要例子不能为压篇幅删掉；复杂主题允许更长 |
| 当前目标 | 一句话，无明确目标时省略或保留探索意图，不编造 |
| 关键理解 | 通常 2–4 点，每点含结论及必要解释/例子，附来源 |
| 未解疑问 | 具体问题、不同意见、失败尝试、待验证之处 |
| 下一步 | 默认一个能开始的动作，区分用户计划与 AI 建议 |
| 相关内容 | 有帮助的资料/旧点子，并注明关联理由 |

短对话允许短总结，没有信息的部分不凑数。正文用短段落与列表，长代码和例子可以展开查看。

### 重点与证据

优先保留用户标记、纠正或采用的内容，其次是理解变化、继续学习的疑问以及可复用的方法/例子/产物。寒暄、重复解释、泛泛鼓励不作为重点，不以 Agent 的篇幅或自信程度判断重要性。

区分 Agent 已解释、用户表示理解、练习已验证。不得把“谈过”概括成“已掌握”。有分歧时保留分歧与来源，不能擅自宣布解决。

### 编辑、刷新与 Markdown

- 按部分编辑并自动保存，保留修订与撤销路径；用户编辑段落优先保留。
- 新生成内容冲突时展示候选变化，不静默覆盖；生成期间又有人工编辑，也不能直接覆盖新版本。
- 区分最新、更新中、有新内容待整理和更新失败；来源缺失时保留可见说明。
- 结构化报告加 Markdown 正文，展示层控制标题层次与间距；支持列表、加粗、引用、链接、代码块，导出组合成 `.md`。
- 不执行原始 HTML；引用可以定位到原消息、材料或文件页码，不能只是一个不可点击的文件名。

## 6. 近期状态与旧点子回归

状态保留原话、来源与有效时间。用户明确表达可影响学习量和推荐，已定计划只提出调整建议。有指定期限就尊重期限，否则默认 7 天；到期停止影响建议但保留记录，用户可提前结束或修正。

行为事实可直接呈现；状态推测经用户确认后生效。观察不到活动不等于用户没有活动。

旧点子通过相关学习/对话出现，附具体关联理由；另有每周最多 3 条回顾，可继续、搁置或不再推荐。没有合适内容就省略，不自动转任务。明确不想开新坑时，暂停需要开启新项目的推荐。

首期在 Mac 应用运行时生成回顾，错过时下次打开补齐一份，不连发多份补偿提醒。这是产品规格，本轮未创建系统定时任务或通知自动化。

## 7. 交付路线

| 阶段 | 内容 | 出口 |
|---|---|---|
| A1：记录与主题 | 独立记录、材料保留、主题关联、原文定位、编辑持久化 | 未分类点子可靠保存并重开 |
| A2：持续学习 | Codex 持续会话、学习方式、资料使用、失败/取消/恢复 | 隔天打开同主题可接着学 |
| A3：可用总结 | 自动整理、Markdown、来源、人工修订保护、过期状态 | 可复习且不歪曲学习事实 |
| A4：找回与状态 | 场景关联、每周回顾、状态有效期与确认规则 | 被忘记的记录在有理由的时刻回来 |
| 后续：Agent 扩展 | DSH、Kimi CLI，验证会话和工具能力 | 用户选择运行时，主题背景延续 |
| 后续：Mac＋安卓 | 本地优先、云端副本、离线记录/阅读/修改、同步 | 两端不必同时在线，内容可流转 |

Agent 扩展与安卓的具体先后依据 A 的使用结果安排，尚未承诺日期。实现阶段须通过对应验收后独立提交。

安卓首版记录、查阅和修改已有内容；AI 在 Mac 执行，Mac 关机时手机不生成新回答或总结。云服务、认证、密钥、加密、删除传播及编辑冲突在同步阶段验证；本轮不选购服务、不上传现有资料。

## 8. A 的验收场景

以下全部为待执行目标，不是本轮已通过的测试。

| ID | 场景与检查步骤 | 合格结果 |
|---|---|---|
| A01 | 无项目/类别输入点子，保存后重启 | 原文和时间保留，无自动任务或 Agent 调用 |
| A02 | 从记录开始主题，加资料，重新打开 | 关系保留，可回原文 |
| A03 | 讨论数轮，隔天继续，分别试两种模式 | 能接续；临时提问不强制课程，带学可跳过改方向 |
| A04 | 完整回复后静默 2 分钟，再输入 | 消息及时保存；异步更新；新增内容不冒充已整理 |
| A05 | Agent 失败、取消、应用重启 | 原始数据保留，状态准确，无假成功 |
| A06 | 只有讲解且无反馈，再补独立练习证据 | 前者不标记掌握，后者仅按证据更新 |
| A07 | 人工改总结后继续聊天，生成中再编辑 | 两次人工修改不被覆盖，候选变化和来源可核对 |
| A08 | 长代码、列表、引用，导出 Markdown | 可读、可导出、来源可定位，不执行 HTML |
| A09 | 网页抓取失败、PDF 部分解析、图片能力缺失 | 原件保留，范围清楚，不宣称完整阅读 |
| A10 | 无期限/指定期限状态及未确认推测 | 默认 7 天或指定期限，到期停止影响，推测不直接生效 |
| A11 | 旧点子与新主题关联，检查每周回顾 | 理由可核对，最多 3 条，不凑数，不再推荐项不反复出现 |
| A12 | 保留点子不执行，再明确落实一条为任务 | 可独立存在；任务可追来源并沿用原流程 |
| A13 | 导出 Obsidian，再修改 Personal OS 原记录 | 主版本明确，不宣称双向合并，不覆盖已有文件 |
| A14 | 完成旧有计划、任务审核和日报流程 | 原任务完成和人工审核语义未改变 |

体验验收：隔一段时间回到主题，能理解关键知识并继续；旧记录的关联理由有用；总结不需反复重写才能使用。需要真实使用反馈，不能仅凭单元测试判定。
