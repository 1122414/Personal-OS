# Agent 运行中实时显示与系统通知计划

日期：2026-09-30

## 目标

1. Agent 运行中就能看到它说了什么、做到哪一步，不用等这一轮结束。
2. Agent 在等你回复、这一轮做完待验收、或执行失败时，Mac 弹系统通知，点击直接打开那个任务的对话。

用户已确认的选择：

- 只在客户端不在前台时通知；正看着客户端时不打扰。
- 等你回复、待验收、失败都通知；自己点取消的不通知。
- 通知用 `/tmp` 数据启动一个测试实例真实验证，由用户在系统弹窗中允许一次。

## 已核对的前提

- 运行中前端每 8 秒拉一次完整状态（空闲 30 秒）。真实库副本的完整状态约 1 MB，其中情报条目约 795 KB，不适合每 1～2 秒拉一次。
- 运行时已逐行解析出回复文字和工具调用（`transcript`），但只在一轮结束时写入数据库；日志 `log_tail` 已按每秒最多一次写入。
- 客户端是 WKWebView，网页的 Notification API 不可用，需要 Swift 调 `UNUserNotificationCenter`。客户端为本机临时签名（`codesign --sign -`），包标识 `app.personal-os.desktop`。
- 客户端固定使用 `~/Library/Application Support/Personal OS/` 下的数据库。

## 设计

### 实时显示

- 运行时在解析出新回复或工具步骤时回调，存储层与日志一起按每秒最多一次写入这一轮的 `transcript`。
- 新接口 `GET /api/agent_runs/running`：只返回运行中的轮次。前端在有运行中的轮次时每 1.5 秒拉一次并合并到现有数据；某一轮离开运行中时完整刷新一次。
- 运行中的一轮显示已有的回复和「执行了 N 步」，末尾显示「正在执行 · 最近一步：…」。只有停在对话底部时才自动跟随。
- 回复末尾的【需要你回复】在运行中还没去掉，前端显示时也去掉。

### 系统通知

- 前端比较前后两次数据：某一轮从运行中变为已回复或失败时，按任务状态生成通知（等你回复、待验收、失败）。这一判断写成独立函数并测试。
- 通过 `window.webkit.messageHandlers.notify` 交给客户端；不在客户端里（浏览器预览）时不做任何事。
- Swift 只在 `NSApp.isActive` 为假时发通知；点击通知激活窗口并跳到 `#tasks/<任务编号>`。第一次发通知前请求授权。
- 客户端支持环境变量 `PERSONAL_OS_DATA_DIR` 指定数据目录，仅用于测试实例，不设置时行为不变。

## 阶段

1. 本计划文档。
2. 实时显示：后端、接口、前端、测试；在 `/tmp` 临时仓库用 Kimi 真实跑一轮。
3. 系统通知：前端判断与测试、Swift 通知与点击跳转、测试数据目录开关。
4. 用 `/tmp` 数据启动测试实例验证通知；验收记录、README；重建客户端。

每阶段测试后中文提交。

## 风险

- 临时签名的应用能否正常请求通知授权，需要实际运行确认。
- 客户端在后台时 WKWebView 的定时器可能被系统降频，通知可能晚几秒。
- 测试实例和正在运行的客户端包标识相同，通知授权是共用的。
