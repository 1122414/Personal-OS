# External session imports retain provenance and user-owned state

- Signals: a newly connected source has many past sessions, contains internal/tool records, or overwrites feedback when it synchronizes.
- Mechanism: import timestamps describe copying, not source recency; copying a pre-read object snapshot back after I/O can overwrite user feedback recorded during the read. A conversation's internal storage may also contain data that is not visible message content.
- Handling: whitelist supported metadata and visible message types; open source SQLite read-only; bound file/line/content sizes; reject path escapes; fingerprint source records; re-read the local record under the write lock to merge source-owned content with current user feedback. Sort by source update/publication time rather than import time. Keep source copies separate from task completion facts.
- Supporting case: WorkBuddy 5.6 adapter (`server/workbuddy.py`, `Store.sync_workbuddy`). Initial native acceptance showed older records first because the batch import order affected local timestamps; explicit source-time sorting fixes it. Concurrent feedback is tested with a read stub that records ignore before sync commits.
- Validation: `tests/test_workbuddy.py` covers source DB hash stability, visible-text filtering, deduplication, concurrent feedback, source failure retention, symlinks, ordering, and task creation without automatic execution. Real local smoke imported 60 records, then 0 new / 0 updated / 60 unchanged / 0 errors. No source transcript content belongs in this experience record.
- Limits: verified once against WorkBuddy 5.6.2 and fixtures on 2026-09-29, not an official API contract. Source format changes must fail visibly rather than erase prior imports. Source deletion is not propagated; there is no cloud sync or task dispatch to WorkBuddy.

## User correction: integrate the useful artifact (2026-09-29)

The user explicitly found the imported WorkBuddy session summaries unhelpful; their desired information was the AI report Markdown already written into Obsidian. Technical import success (60 records, zero duplicates) did not validate product usefulness. Before choosing a source, identify the actual reading/decision artifact and its existing location. Execution transcripts and completed reports have different roles.

The corrected primary experience reads dated report files directly (`server/reports.py`, `DailyReports.jsx`), retains file provenance and dates, and defaults Intelligence/Today to those reports. Existing conversations stay behind a secondary tab, are excluded from AI brief context, and the user's prior auto-import was disabled. Six tests in `tests/test_reports.py` cover live read/update, filesystem boundaries, HTTP routes, setting persistence and context filtering. Real-source inspection found 22 reports over five dates; browser acceptance verified AI HOT body text, date switching, table/checklist rendering and a source update. This validates the chosen artifact once; it is not a claim that every future WorkBuddy output will use the same folder layout.
