## 已配置的 WorkBuddy

- 数据源：本机 `~/.workbuddy`，针对安装的 5.6.2 格式核验。仅读取 `sessions` 元数据和对应 JSONL 用户/助手可见文字，不读取认证文件、推理或工具日志。
- 实际客户端库已启用同步，起始日期 2026-09-22。此日期是固定下限，未来更新会继续进入；不是每次删除 7 天前记录。可在 Settings 修改。
- 源数据库以只读 URI 打开；每条外部 ID 固定映射本地记录。更新正文时保留已读/收藏/忽略和项目关联，资料按原会话更新时间倒序显示。
- 首次备份：`~/Library/Application Support/Personal OS/backups/backup-20260929-024611-0cd5a104.sqlite3`。没有对生产库执行恢复。
- 单次最多检查 1,000 会话、单文件 32 MB、总读取 64 MB；正文保留最多最后 20 条消息/30,000 字符，最近回复最多 5,000 字符；有截断或坏行会提示。附件/实际产物文件不会因导入会话而自动复制。
- 本地格式升级/缺正文时报告错误且保留上次内容；已导入副本不随源删除。当前没有跨设备 WorkBuddy 同步、OAuth 云 API 或向 WorkBuddy 下发任务。
- 自动导入本身不调用模型。沿用应用 AI 建议功能时，相关情报标题会作为上下文传给 Codex；从资料创建 Agent 任务后，任务描述里的来源摘要也随执行发送。

## 现在的使用方式

1. 重新打开 `build/Personal OS.app`，加载最后一轮排序修复。Settings → WorkBuddy 可查看最近同步；已保存路径、日期并启用运行时同步，不必重复配置。
2. Intelligence → WorkBuddy：查看来源和会话文本，忽略无用信息、收藏有用信息。这里也会出现自动化维护会话；尚未配置自动分类/噪声过滤。
3. 要落实的内容点“创建任务”，填写完成标准、选择项目；要作为笔记的内容点“提出知识沉淀”，到 Review 核对再写入。原来源若已有同一笔记，先核对是否需要再次沉淀。
4. Projects 建实际项目；需要 Codex 执行时设置本地工作目录。Tasks 建小任务，Today 选择并确认计划；后续可“调整计划”。
5. 执行后在 Review 核验；晚间 History 生成/刷新日报，核对后“结束今天”。漏记可选择过去日期补记。
6. Settings 可备份/导出。恢复前自动备份当前数据；备份范围只有工作台数据库，项目文件和 Obsidian 需要各自的保护方式。

MVP 下一道门槛是实际使用：连续 7 天记录第一入口使用率、昨日记录是否可用、Agent 任务从本工作台发起并返回的比例。外部 WorkBuddy 会话导入不计入“从 Personal OS 发起 Agent 任务”的比例。三个尚未确定的新模块继续等待真实使用后的定义。
